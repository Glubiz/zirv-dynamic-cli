### 2026-08-19: dashboard click-drag selection + OSC 52 copy; Alt+Enter folding fix; mail-loss fix for issue #30 (`feat/dash-adaptive-poll-help-overlay`, uncommitted, v2.13.0)
**What:** Three changes extending PR #29 (the adaptive-poll/help-overlay branch), uncommitted. ### 2026-08-19: adaptive dashboard input-poll wait; `Ctrl+A ?` help overlay
**What:** Two independent dashboard usability fixes, on `feat/dash-adaptive-poll-help-overlay` (PR #29, committed `ddff811`). (1) The event loop's first `event::poll` wait per tick is now adaptive (`input_poll_wait`): 10ms while within 300ms of the last operator keyboard/mouse event, else the old flat 50ms. Keystrokes always reached the pane's pty instantly, but the repaint showing the child's echo of them waited out the old flat 50ms poll, making typing feel debounced. Pane output deliberately does not refresh the hot window (a streaming/spinning pane cannot hold the loop at 10ms), so idle and streaming CPU are unchanged; `last_activity` is seeded at launch. (2) New `Ctrl+A ?` (aliases `h`/`H`) help overlay listing every binding, closed by any key. Content is a compile-time `HELP_BINDINGS` table sync-tested against the real `filter_key` dispatch and checked exhaustively against all 16 `DashAction` variants (no wildcard arm), so a future action can't be added without a help-row decision; width (49 cols) and height (fits 80x24) are both asserted by tests.
**Key changes:** `dash/mod.rs` (`DashAction::Help`, `input_poll_wait`, `INPUT_POLL_{HOT,IDLE}_WAIT`/`_WINDOW`, `last_activity`), `dash/ui.rs` (`Overlay::Help`, `HelpBinding`, `HELP_BINDINGS`, `help_lines`).
