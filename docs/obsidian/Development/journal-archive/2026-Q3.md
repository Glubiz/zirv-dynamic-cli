### 2026-08-26: sandbox-escape allowlist + durable interactive-mode pinning (`fix/147-sandbox-escape-allowlist`, v2.31.0, issue #147, PR #154)
**What:** New `[safety] escape_allow` policy layer (operator-home-only, `REPO_FORBIDDEN`, seeded with a built-in read-only-utility subset of `SHIPPED_POSTURE_ALLOW`) narrows the sandbox-escape gate: every executable segment of a `--dangerously-disable-sandbox` retry must match `escape_allow` AND clear a new credential-path/root-scan screen (`escape_denied_by_screen`) before the escalation branch leaves an already-`Allow` verdict alone (matched `<sandbox: escape_allow>`), alongside the existing `gh` carve-out. The native claude settings `permissions.ask = ["Bash(dangerouslyDisableSandbox:true)"]` rule is removed outright — documented Claude behavior makes a native rule independent of the `PreToolUse` hook's own decision, so it silently defeated every hook-side escape `allow`. `sandbox.filesystem.allowWrite` now scopes the mail directory so `zirv ctx send` works sandboxed. `permissions.rs`'s claude extractor now correlates against zirv's own safety-decision log instead of guessing cause from denial text, and surfaces accepted/pending/denied interactive sandbox-escape asks for the first time; a new `permissions compile --escape` flag (claude only) writes eligible accepted asks into `[safety] escape_allow`, and both audit/compile surfaces now warn when a recommended family would still be blocked by the operator's own native claude rule.

Finishing round (PR #154) added two more fixes on top: (1) CI's "Run Tests" failure (`commands::workflow::artifact::tests::a_server_command_that_exits_immediately_is_a_failure`, ubuntu, cargo-nextest exit 100) was a genuine race — `run_interactive_with`'s failure branches read `spawn_stderr_drain`'s tail mutex the instant `try_wait`/`terminate_process_tree` observed the child dead, with no synchronization against the reader thread having actually drained the pipe yet, so a child that printed to stderr and exited in the same instant could lose that line under CI's scheduling. `spawn_stderr_drain` now also returns its `JoinHandle`, and both failure branches call a new bounded `wait_for_stderr_drain` (`STDERR_DRAIN_BUDGET` = 500ms, mirrors `supervise::FINAL_DRAIN_BUDGET`'s identical fix for the analogous `OutputTap` race) before reading the tail. (2) Durable interactive-mode pinning: the hook (`run_check_hook_mode_with_env`) used to classify `LaunchMode` from Claude's self-reported `permission_mode` alone, so an operator whose native `defaultMode` is `"auto"` (not `"default"`/`"plan"`/`"acceptEdits"`) had every genuinely interactive session fail closed to `Headless`, asking on everything. A new `adapters::LAUNCH_MODE_ENV` (`ZIRV_CTX_LAUNCH_MODE=interactive`) is pushed into `turn_env` at every real interactive-launch seam — `wrap.rs::run_with` (covers `zirv ctx wrap` and, via `chat.rs`, `zirv chat`'s wrap fallback), `dash/mod.rs::run_dashboard`'s first/orchestrator pane (always interactive), and `dash/mod.rs::fulfill_spawn_request`'s worker panes (gated on the identical `req.interactive` signal `worker_pane_extra_args` already uses) — reusing each site's existing `LaunchMode`/interactivity signal rather than re-deriving it. The hook's own `safety::launch_mode_pinned_interactive(env)` trusts the pin over an unproven self-report; listed in `sessions::SUPERVISION_ENV` so a nested headless launch (`exec`/`loop`, or a non-interactive spawn request) never inherits its parent's proof.
**Key changes:** `commands/ctx/safety.rs` (`escape_allow`, `builtin_escape_allow`, `escape_denied_by_screen`, `escape_allow_matches`, `command_fails_escape_screen`, `SANDBOX_DENY_READ_HOME_PATHS`, `launch_mode_pinned_interactive`), `commands/ctx/config.rs` (`REPO_FORBIDDEN` entry), `commands/ctx/adapters/claude.rs` (`launch_settings_value`'s third `mail_write_dir` param, native ask rule removed), `commands/ctx/adapters/mod.rs` (`LAUNCH_MODE_ENV`, `LAUNCH_MODE_INTERACTIVE_VALUE`, `launch_mode_pin_env`), `commands/ctx/sessions.rs` (`SUPERVISION_ENV` grown to 5), `commands/ctx/wrap.rs` (`turn_env` pin push), `commands/ctx/dash/mod.rs` (pin push at both pane-spawn seams), `commands/ctx/log.rs` (`SafetyDecisionRecord`/`read_safety_decisions`), `commands/ctx/permissions.rs` (`permission_mode`/`is_sidechain` fields, `correlate_safety_decision`, `AuditReport.requests`, `CompileArgs.escape`, `escape_eligibility`, `read_native_claude_rules`/`native_conflict`), `commands/setup.rs` (`union_home_safety_escape_allow`/`read_home_safety_escape_allow`), `commands/workflow/artifact.rs` (`spawn_stderr_drain`/`wait_for_stderr_drain` race fix). `Cargo.toml` bumped to 2.31.0.

**Review round 1 (2026-08-27) fixed two escalations found in the above, both landed in the same PR #154 before merge.** (1) CRITICAL: `escape_denied_by_screen` never checked for unquoted output/input redirection, so a seeded read-only family's own pattern (e.g. `"echo *"`) matched straight through a trailing ` > ~/.claude/settings.json` — an unsandboxed *write* via the built-in escape seed, in both interactive and headless mode.
