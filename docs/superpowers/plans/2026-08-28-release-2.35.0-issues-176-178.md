# Release 2.35.0: Issues #176, #177, and #178

This file is the durable implementation ledger for the draft release PR. Work is performed and committed one issue at a time; the PR body mirrors the same checklist.

Base: `main` at `c6b4438` (v2.34.0)

Branch: `release/2.35.0`

## Global constraints

- Keep every command-policy pattern portable across repositories, shells, operating systems, and machines. Never persist a developer path, checkout name, environment value, or one-off command spelling as a general allow rule.
- When a safe general pattern cannot express the operation, tell the agent how to use a non-escalating alternative instead of proposing the one-off command for an allow list.
- Safe issue/PR operations cover GitHub PR and issue creation, updates, and comments, plus GitLab MR and issue creation, updates, and comments.
- Merges, close/reopen lifecycle changes, deletes, releases, authentication changes, arbitrary API calls, redirects, and shell composition stay gated.
- Add inline tests for every behavior change and run all five repository verification gates before the PR is marked ready.
- Keep `Cargo.toml` and `Cargo.lock` at v2.35.0, above the v2.34.0 base.

## #176 — `zirv report`

- [ ] Add `zirv report bug|feature <title>` raw-argv dispatch and reserve the built-in name.
- [ ] Accept `--body` or `--body-file`, append version/OS/architecture and safe session harness/model context, and never include a session identifier.
- [ ] File against `Glubiz/zirv-dynamic-cli` with the correct `bug` or `enhancement` label.
- [ ] Resolve credentials in documented order: `gh auth token --hostname github.com`, `GH_TOKEN`, `GITHUB_TOKEN`, then operator-owned `~/.zirv/.settings.toml`; never trust repository settings for the token.
- [ ] Print only the created issue URL on success and provide a clear credential/setup error.
- [ ] Update built-in help, generated context files, and vault documentation.
- [ ] Run focused tests and commit #176 before opening #177 implementation work.

## #177 — reliable inter-agent messaging

- [ ] Reject implicit undirected single-claim sends; retain that behavior only behind explicit `--claim-once`.
- [ ] Add stable message IDs, sender-visible queued/delivered/read/expired state, per-recipient receipts, TTL, and dead letters without breaking legacy Markdown mail.
- [ ] Add `--reply-to`, thread correlation, intent/topic metadata, and thread-filtered inbox output.
- [ ] Add role addressing, using live session registry roles and per-session fan-out receipts.
- [ ] Reuse nudge markers as the best-effort low-latency wake path after the durable write.
- [ ] Render one model-agnostic envelope across harnesses; label payload as information, not instructions, and include original/stored size hints.
- [ ] Extend `zirv ctx status` with per-session queue depth, unread count, and recent message flow.
- [ ] Update ctx/supervisor/untrusted-input documentation, run focused tests, and commit #177 before opening #178 implementation work.
